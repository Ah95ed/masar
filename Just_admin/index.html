1. رابط الخدمة

استبدل النطاق التالي بنطاق الخادم الذي نُشر عليه المشروع. إذا كان المشروع في جذر النطاق يكون الرابط:

https://your-domain.example/api/auth.php?route=login
    https://your-domain.example/api/management.php?route=dashboard
    https://your-domain.example/api/engineer.php?route=tasks
    https://your-domain.example/api/accounting.php?route=accounts
    https://your-domain.example/api/warehouse.php?route=warehouse-items
    https://your-domain.example/api/maintenance.php?route=repairs

يوجد توافق خلفي للمسارات القديمة عبر api.php?route=...؛ التطبيقات الجديدة تستخدم نقطة دخول القسم المخصصة، مع Bearer token مشترك.

مهم: استخدم عنوان Maxlond المنشور مع HTTPS وشهادة صالحة في الإنتاج. لا ترسل كلمات مرور أو توكنات عبر HTTP غير مشفر.

كل الاستجابات JSON بترميز UTF-8. النجاح بالشكل {"success":true,"data":...}، والخطأ بالشكل {"success":false,"error":{"code":"...","message":"..."}}.

أرسل الترويسة Accept: application/json دائماً. مع JSON POST أرسل أيضاً Content-Type: application/json.

3. تطبيقات Flutter حسب القسم

هذه مواصفات خمسة تطبيقات/واجهات مستقلة. يمكن إصدارها كتطبيقات Flutter منفصلة أو flavors في مستودع واحد؛ لكل واجهة تنقلها وصلاحياتها، وتشترك جميعها في المصادقة والنماذج البرمجية.

ترحيل مطلوب للحسابات: شغّل migrations/20261003_add_accountant_role.sql مرة واحدة على قاعدة الاستضافة قبل إنشاء حساب محاسب. أدوار هذا الإصدار: admin، engineer، accountant. واجهتا المخزن والصيانة تستخدمان حساب المدير حالياً ولا تمنحان دوراً مستقلاً.

تطبيق الإدارة · role admin

شاشات: لوحة المؤشرات وترتيب الإنجاز، المواقع، خطط العمل، مراجعة التقارير، المستخدمون، الآليات، المخزن، الصيانة، الحسابات والقيود.

API الإدارة: /api/management.php?route=.... أهم المسارات: dashboard، sites/site-save/site-cancel، tasks/work-plan-save/work-plan-cancel، reports/report-review، users/user-save/user-status، machinery/machinery-save/machinery-status، وجميع مسارات المخزن والصيانة والمحاسبة الموضحة في تبويباتها.

برومبت مطور تطبيق الإدارة
أنشئ تطبيق Flutter عربي RTL باسم Maxlond Management للمدير فقط. استخدم Material 3، تقسيماً واضحاً للمواقع والموارد والمالية، وحالات تحميل/فراغ/خطأ/انقطاع اتصال. اجعل واجهة الإدارة منفصلة عن تطبيق المهندس والمحاسب.

المصادقة المشتركة: POST /api/auth.php?route=login بجسم JSON {"username":"...","password":"...","device_info":"Maxlond Management"}. اقبل role=admin فقط، خزّن token في flutter_secure_storage، وأرفق Authorization: Bearer TOKEN وAccept: application/json. ارفض الدخول إلى هذه الواجهة إذا كان الدور غير admin. نفّذ logout عبر POST /api/auth.php?route=logout.

Base URLs بعد النشر: https://DOMAIN/api/management.php?route= وhttps://DOMAIN/api/auth.php?route=. لا تثبت النطاق داخل الشيفرة. جميع POST JSON إلا report-receipt فهو multipart/form-data.

الشاشات والـAPI:
- لوحة المدير: GET dashboard. اعرض sites وengineers وmachinery وpending_reports وinventory_value وtoday_top_engineers. عناصر الترتيب: engineer_id وfull_name وscore وactivity_count وcompleted_tasks.
- المواقع: GET sites؛ POST site-save لإنشاء/تعديل (id اختياري، name، client_name، work_date، start_time، end_time، location، budget، status، manager_id، description)؛ POST site-cancel مع site_id للأرشفة بحالة cancelled بدلاً من حذف التاريخ.
- خطط العمل: GET tasks مع site_id/status اختياريين؛ POST work-plan-save بحقول site_id وtitle وdescription وassigned_to وis_broadcast وpriority؛ POST work-plan-cancel مع task_id.
- التقارير: GET reports مع status/site_id، أو GET reports&id=ID للتفاصيل والمصروفات والإيصالات؛ POST report-review مع report_id وdecision=approved|rejected وadmin_notes. الاعتماد ينشئ قيد المصروفات عند توفر الحسابات. لا تعدّل التقارير المعتمدة.
- المستخدمون: GET users؛ POST user-save لإنشاء مهندس أو محاسب أو تعديل بياناته، والإنشاء يتطلب كلمة مرور من 10 أحرف؛ POST user-status للتفعيل/التعطيل. لا تعرض كلمة المرور بعد الإنشاء ولا تسمح بتعطيل حساب المدير الحالي.
- الآليات: GET machinery؛ POST machinery-save؛ POST machinery-status. المخزن: GET warehouse-items وwarehouse-categories وwarehouse-moves؛ POST warehouse-item-save وwarehouse-category-save وwarehouse-item-status وwarehouse-move-create. الصيانة: GET repairs وGET repairs&id=ID؛ POST repair-create/repair-update/repair-status.
- الحسابات: GET accounts وjournal وjournal-entry&id=ID وfinancial؛ POST account-save وaccount-delete وjournal-create. لا تسمح بحذف حساب مستخدم بقيد، ولا تعدّل/تحذف قيداً مرحلاً؛ أنشئ قيداً عكسياً للتصحيح.
- الإشعارات: GET notifications؛ POST notification-read أو notification-read-all.

اعرض رسائل error.message للمستخدم بعد تنقيحها. 401 يعيد للدخول، 403 صلاحية، 404 غير موجود، 409 تعارض، 422 تحقق مدخلات، 429 تهدئة المحاولات، و500 رسالة عامة. اكتب نماذج Dart وخدمة API مركزية واختبارات تحليل JSON والصلاحيات، ولا تخترع مسارات غير موثقة.

تطبيق المهندس · role engineer

يركز على المهام اليومية والتقارير والمرفقات والإشعارات؛ لا تظهر فيه أدوات الإدارة أو المالية.

API المهندس: /api/engineer.php?route=.... المسارات: dashboard، sites، tasks، task-update، reports، report-receipt، notifications، notification-read، notification-read-all.

برومبت مطور تطبيق المهندس
أنشئ تطبيق Flutter عربي RTL باسم Maxlond Engineer لمهندس الموقع. استخدم Material 3 وشريط تنقل سفلي: الرئيسية، مهامي، تقاريري، الإشعارات. لا تعرض الشاشات المالية أو أدوات المدير.

سجّل الدخول من POST /api/auth.php?route=login، وتحقق أن role=engineer. احفظ Bearer token في flutter_secure_storage ولا تسجله. استخدم /api/engineer.php?route= مع Authorization وAccept JSON، والخروج من /api/auth.php?route=logout.

الشاشات: لوحة من dashboard (open_tasks, completed_tasks, pending_reports, approved_reports)؛ المواقع من sites؛ المهام من tasks مع مرشحات site_id/status؛ تفاصيل المهمة وتحديثها عبر POST task-update بجسم {"task_id":12,"progress":65,"status":"in_progress","note":"..."}. التقدم من 0 إلى 100، وdone يجعل التقدم 100.

أنشئ تقريراً عبر POST reports بالحقول site_id, report_date بصيغة YYYY-MM-DD, weather, temperature, workers_count, machinery_count, work_done, issues, materials_used, safety_notes, progress_percent, expenses. المصروفات قائمة بها item_name/category/quantity/unit_price/notes. إعادة الإرسال قبل الاعتماد تحدث التقرير ومصروفاته؛ 409 يعني أنه معتمد.

قائمة التقارير من GET reports، والتقرير المفرد ومصروفاته ومرفقاته من GET reports&id=ID. ارفع الإيصال بعد التقرير إلى POST report-receipt كـmultipart مع report_id وreceipt؛ يقبل JPEG/PNG/WebP/PDF بحد 5MB. اعرض المسار file_path كرابط ضمن نطاق التطبيق. الإشعارات من notifications، وPOST notification-read أو notification-read-all.

تعامل مع التحميل والفراغ والانقطاع و401/403/409/422/429، وخزن المسودات محلياً فقط مع بيان عدم المزامنة. أضف اختبارات للنماذج والخدمات والصلاحيات، ولا تسمح للمهندس باعتماد تقاريره.

تطبيق الحسابات · role accountant

تطبيق مستقل محمي بدور accountant؛ لا يصل إلى إدارة المستخدمين أو المهام أو مراجعة التقارير. يتطلب ترحيل قاعدة البيانات المبين أعلاه.

API الحسابات: /api/accounting.php?route=.... المصادقة نفسها، لكن ارفض أي حساب لا يحمل الدور accountant.

برومبت مطور تطبيق الحسابات
أنشئ تطبيق Flutter عربي RTL باسم Maxlond Accounting لموظفي الحسابات. صفحات التطبيق: ملخص مالي، دليل الحسابات، إنشاء/تعديل حساب، القيود اليومية، تفاصيل القيد، قيد جديد، ميزان المراجعة. أظهر الأرصدة والتصنيفات بوضوح ووفّر بحثاً ومرشحات تاريخ.

سجّل الدخول عبر POST /api/auth.php?route=login، ولا تقبل إلا role=accountant. خزّن Bearer token بأمان، واستعمل /api/accounting.php?route= للمسارات المالية. لا تعرض زر اعتماد تقارير أو إدارة مستخدمين أو مواقع.

GET dashboard يعيد accounts_count, assets, liabilities, equity, revenue, expenses, net_profit, posted_entries. GET accounts يعيد دليل الحسابات والأرصدة؛ POST account-save ينشئ/يحدّث account code/name/type/parent_id/description/is_active. POST account-delete بجسم {"account_id":ID}؛ توقع 409 إذا استُخدم الحساب في قيد أو له رصيد.

GET journal يدعم from وto بصيغة YYYY-MM-DD. GET journal-entry&id=ID يعيد تفاصيل البنود. POST journal-create بجسم {"description":"...","site_id":4,"lines":[{"account_id":2,"debit":100,"credit":0,"description":"..."},{"account_id":10,"debit":0,"credit":100,"description":"..."}]}. اعرض تنبيه عدم التوازن ولا ترسل القيود غير المتوازنة. GET financial يعيد balances وnet_profit وtrial_balance.

لا توفر تعديل/حذف للقيود المرحلة؛ التصحيح يتم بقيد عكسي موثق. لا تسمح بتغيير نوع حساب مستخدم في قيد. احمِ جميع البيانات الحساسة بالتخزين الآمن، واختبر توازن القيد و409/422.

تطبيق المخزن · صلاحية المدير الحالية

هذا التطبيق واجهة متخصصة للمخزون، لكنه يستخدم حالياً حساب المدير لعدم وجود دور أمين مخزن في مخطط المستخدمين.

برومبت مطور تطبيق المخزن
أنشئ تطبيق Flutter عربي RTL باسم Maxlond Warehouse لإدارة المخزن ضمن شركة Maxlond. حتى يضاف دور أمين مخزن مستقل، اشترط role=admin ولا تخزن بيانات دخول مشتركة داخل التطبيق. استخدم /api/warehouse.php?route= مع Bearer token.

الصفحات: لوحة المواد المنخفضة، المواد، الفئات، سجل الحركات. GET warehouse-items يدعم low=1 وcategory_id؛ GET warehouse-categories؛ GET warehouse-moves وitem_id اختياري. POST warehouse-item-save لإنشاء/تعديل code/name/category_id/unit/min_quantity/unit_price/location/notes، ولا تغيّر الرصيد من نموذج المادة. POST warehouse-category-save لإضافة/تعديل الاسم والوصف. POST warehouse-item-status لتعطيل المادة دون حذف سجلها.

سجّل كل الوارد والصادر والتسوية عبر POST warehouse-move-create بجسم item_id/type/quantity/unit_price/site_id/supplier/invoice_number/reason. type من in/out/adjust. اعرض الرصيد قبل وبعد، وارفض الصرف الأعلى من المتاح، ولا تعِد إرسال الطلب تلقائياً بعد مهلة غير مؤكدة. استجابة الصرف تتضمن item_id/quantity/type. الحركة تنشئ قيداً محاسبياً تلقائياً للوارد والصادر إذا كانت الحسابات موجودة.

اعرض تأكيداً قبل التسوية، سجلاً زمنياً لكل حركة، وأخطاء 409/422 بشكل مفهوم. لا توفر حذفاً للحركات؛ التسويات حركة جديدة موثقة.

تطبيق الآليات والصيانة · صلاحية المدير الحالية

واجهة مستقلة للآليات وطلبات الإصلاح، تستخدم حالياً حساب المدير مثل المخزن.

برومبت مطور تطبيق الصيانة
أنشئ تطبيق Flutter عربي RTL باسم Maxlond Maintenance لفريق إدارة الآليات والصيانة. حالياً يجب التحقق من role=admin. استخدم /api/maintenance.php?route= مع Bearer token، والمصادقة من /api/auth.php?route=login.

الصفحات: قائمة الآليات وحالاتها، طلبات التصليح المفتوحة، تفاصيل الطلب مع قطع الغيار والكلفة، إنشاء/تعديل طلب، وتحديث الحالة. GET machinery؛ POST machinery-save لإنشاء/تعديل بيانات الآلية؛ POST machinery-status لتغيير الحالة المتاحة/قيد الاستخدام/الصيانة/خارج الخدمة. GET repairs وGET repairs&id=ID؛ POST repair-create أو repair-update ببيانات machinery_id/title/description/problem_type/priority/technician_name/workshop/labor_cost/notes/parts، وكل part يحوي part_name/quantity/unit_price. POST repair-status مع repair_id/status.

الحالات: pending, in_progress, waiting_parts, completed, cancelled. اعرض مجموع أجور العمل وقطع الغيار. الطلبات المكتملة أو المرتبطة بقيد مالي مقفلة للتعديل؛ عند إكمال إصلاح ذي تكلفة يرحّل النظام قيد صيانة تلقائياً. لا تحذف طلبات التصليح أو أجزاءها من واجهة الهاتف. أضف تحققاً للمدخلات واختبارات لحالات إقفال الطلب وتزامن الرصيد.

2. تسجيل الدخول وإدارة التوكن

POST?route=loginلا يحتاج توكناً

يسمح بتسجيل الدخول باسم المستخدم أو البريد الإلكتروني وكلمة المرور. يجب أن يكون الحساب نشطاً ومعتمداً من الإدارة.

{
  "username": "engineer.username",
  "password": "كلمة المرور",
  "device_info": "Maxlond Flutter / Android"
}

الاستجابة الناجحة تتضمن data.token وdata.token_type بقيمة Bearer وdata.expires_in بالثواني، إضافة إلى ملف المستخدم العام.

{
  "success": true,
  "data": {
    "token": "64-hex-characters",
    "token_type": "Bearer",
    "expires_in": 2592000,
    "user": {
      "id": 14,
      "full_name": "اسم المهندس",
      "username": "engineer.username",
      "email": "engineer@example.com",
      "role": "engineer"
    }
  }
}

عمر التوكن 30 يوماً. يخزن الخادم بصمة SHA-256 للتوكن فقط. لا توجد نقطة تجديد للتوكن؛ عند انتهائه سجّل الدخول مجدداً. خزّن التوكن في التخزين الآمن على الجهاز، ولا تضعه في السجلات أو رسائل الأخطاء.

أضف إلى كل طلب محمي: Authorization: Bearer <token>. الـ API لا يستخدم جلسة الموقع ولا رمز CSRF الخاص بنماذج الويب.

GET?route=meبيانات المستخدم الحالي
POST?route=logoutإبطال التوكن الحالي؛ أرسل جسم JSON فارغاً أو بدون جسم

4. لوحة المؤشرات والمواقع والآليات

مسار dashboard يعيد حقولاً مختلفة حسب الدور:

  • المدير: sites، engineers، machinery، pending_reports، inventory_value، ومصفوفة today_top_engineers.
  • المهندس: open_tasks، completed_tasks، pending_reports، approved_reports.
  • المحاسب: accounts_count، assets، liabilities، equity، revenue، expenses، net_profit، posted_entries.

كل عنصر في today_top_engineers يحوي engineer_id وfull_name وscore وactivity_count وcompleted_tasks. التقييم متوسط نسب الإنجاز المسجلة اليوم في التقارير وتحديثات المهام؛ النتائج مرتبة تنازلياً ومحدودة بأعلى 7 مهندسين.

المهندس يرى المواقع النشطة أو المخطط لها أو المتوقفة التي لا مدير لها أو التي عُيّن مديرها له. المدير يرى جميع المواقع. قائمة المواقع محدودة بـ500 سجل، والمهام بـ200، والتقارير والإشعارات بـ100 سجل.

الآليات متاحة لكل مستخدم مسجل دخوله؛ تتضمن الاستجابة الحالة وكلفة الساعة والمشغل ورقم اللوحة.

5. المهام وتحديث تقدمها

المهندس لا يرى إلا المهام المسندة إليه أو المعممة. المدير يستطيع قراءة جميع المهام، لكنه لا يستطيع إرسال تحديث مهندس عبر هذا المسار.

POST?route=task-update
{
  "task_id": 12,
  "progress": 65,
  "status": "in_progress",
  "note": "اكتمل صب الجزء الأول"
}

التقدم عدد صحيح من 0 إلى 100. الحالات المقبولة: pending، in_progress، review، done. عند اختيار done يضبط الخادم التقدم إلى 100، ويحفظ سجل التحديث ويرسل إشعاراً إلى المديرين.

6. التقارير اليومية

للقائمة أرسل GET ?route=reports. يمكن الترشيح باستخدام &status=submitted أو &site_id=4. لعرض تقرير مفرد مع المصروفات والمرفقات أرسل GET ?route=reports&id=28. المدير يرى كل التقارير، والمهندس يرى تقاريره فقط.

أرسل JSON إلى POST ?route=reports. التاريخ بصيغة YYYY-MM-DD، والموقع يجب أن يكون متاحاً للمهندس.

{
  "site_id": 4,
  "report_date": "2026-10-01",
  "weather": "مشمس",
  "temperature": 31.5,
  "workers_count": 12,
  "machinery_count": 2,
  "work_done": "صب أساس القطاع الشرقي",
  "issues": "",
  "materials_used": "أسمنت وحديد",
  "safety_notes": "تم استخدام معدات الوقاية",
  "progress_percent": 35,
  "expenses": [
    {
      "item_name": "أسمنت",
      "category": "materials",
      "quantity": 8,
      "unit_price": 9500,
      "notes": ""
    }
  ]
}

تصنيفات المصروفات: materials، labor، fuel، equipment، transport، other.

يوجد تقرير واحد لكل مهندس وموقع وتاريخ. الإرسال مرة ثانية قبل الاعتماد يحدّث التقرير ويستبدل بنود مصروفاته. الإيصالات السابقة تبقى محفوظة. التقرير المعتمد لا يقبل التعديل ويعيد 409. نجاح الإنشاء يعيد 201 والتحديث يعيد 200.

مراجعة المدير من التطبيق

أرسل للمدير POST ?route=report-review بجسم JSON. الاعتماد ينشئ قيد المصروفات تلقائياً عند توفر حسابات المصروفات والنقدية.

{"report_id": 28, "decision": "approved", "admin_notes": "تمت مراجعة الإيصالات"}

قيمة decision هي approved أو rejected. إعادة مراجعة تقرير سبق البت فيه تعيد 409، وغياب الحسابات المحاسبية المطلوبة للاعتماد يعيد 409 account_setup_required.

7. رفع الإيصالات

ارفع كل ملف منفرداً إلى POST ?route=report-receipt بنوع محتوى multipart/form-data، مع الحقلين التاليين:

  • report_id: رقم التقرير.
  • receipt: ملف واحد من JPEG أو PNG أو WebP أو PDF، حتى 5 ميغابايت.
final form = FormData.fromMap({
  'report_id': reportId,
  'receipt': await MultipartFile.fromFile(file.path),
});

أرسل ترويسة Bearer مع رفع الملف. يتحقق الخادم من نوع MIME ويحفظ الملف باسم عشوائي. المهندس يرفع مرفقاً لتقريره فقط، ويمكن استرجاع قائمة المرفقات ضمن GET ?route=reports&id=ID في الحقل data.receipts. الحقل file_path مسار نسبي إلى جذر التطبيق.

8. الإشعارات

GET?route=notifications

يعيد إشعارات المستخدم المسجل دخوله فقط.

POST?route=notification-read
{"notification_id": 28}

يعيد notification-read حالة الإشعار بعد تعليمه كمقروء. لتعليم جميع إشعارات المستخدم الحالي أرسل POST ?route=notification-read-all دون جسم؛ يعيد data.updated_count.

9. الأخطاء والاستجابات

رمز HTTPالمعنىالتصرف المقترح في التطبيق
200نجاح أو تحديثاقرأ البيانات من data.
201تم الإنشاءاعرض النجاح وخذ المعرف من الاستجابة.
204طلب تمهيدي للمتصفحلا يوجد جسم استجابة.
400مسار أو JSON غير صالحراجع المسار أو صيغة JSON.
401توكن مفقود أو منتهٍ أو بيانات دخول خاطئةأعد تسجيل الدخول عند انتهاء التوكن.
403الدور أو الحساب لا يملك الصلاحيةاعرض رسالة مناسبة ولا تعاود الطلب تلقائياً.
404مسار أو مورد غير موجودتحقق من المعرف والصلاحية.
405طريقة HTTP غير مدعومةاستخدم الطريقة الموضحة في جدول المسارات.
409تعارض، مثل تقرير معتمدأبلغ المستخدم أن التقرير مقفل.
422بيانات غير صالحةاعرض أخطاء التحقق بجانب الحقول.
429محاولات دخول كثيرةأوقف المحاولات وأظهر الانتظار 15 دقيقة.
500خطأ خادماعرض رسالة عامة ولا تعرض تفاصيل الخادم.

تكون رسالة الخطأ داخل error.code وerror.message. تعامل مع انقطاع الشبكة والمهلات أيضاً، فليست كل الأخطاء استجابة JSON.

10. مثال اتصال Flutter

المثال التالي يستخدم حزمتَي http وflutter_secure_storage. احفظ التوكن بأمان ولا تطبعه في سجل التطوير.

final response = await http.get(
  Uri.parse('$baseUrl/api.php?route=tasks'),
  headers: {
    'Accept': 'application/json',
    'Authorization': 'Bearer $token',
  },
);

final Map<String, dynamic> json = jsonDecode(response.body);
if (response.statusCode < 200 || response.statusCode >= 300) {
  final message = json['error']?['message'] ?? 'تعذر تنفيذ الطلب';
  throw ApiException(message, response.statusCode);
}
final List<dynamic> tasks = json['data'] as List<dynamic>;

جهّز معالجاً موحداً للاستجابات، وأرفق التوكن بالطلبات المحمية، ونفّذ تسجيل الخروج بإبطال التوكن ثم احذفه من التخزين الآمن محلياً.

11. حدود الواجهة الحالية

ابنِ التطبيق على العمليات الموجودة أدناه فقط. لا تعرض أزرار حفظ لعمليات لا تملك مسار API.
متاح
مصادقة موحدة، واجهات منفصلة للأدوار، إدارة مواقع وخطط ومستخدمين وآليات، تقارير ومراجعتها، مخزن وحركات، صيانة وقطع غيار، دليل حسابات وقيود وميزان مالي، وإشعارات.
غير متاح
تجديد التوكن، تنزيل محمي لملفات الإيصالات عبر وسيط API، ودور مستقل لأمين المخزن أو فني الصيانة. واجهتا المخزن والصيانة تستخدمان دور المدير حالياً.

الدور accountant محدود بالحسابات والقيود والتقارير المالية. المهندس يرى مهامه وتقاريره فقط. المدير يدير بقية أقسام النظام. تعطيل المستخدم يبطل توكناته.

مرجع قديم

البرومبت العام أدناه مخفي لأنه سابق لتقسيم تطبيقات Maxlond؛ استخدم برومبت التطبيق المناسب في تبويب تطبيقات Flutter.

مواصفات تنفيذ تطبيق Maxlond
أنت مطور Flutter خبير. أنشئ تطبيقاً عربياً متكاملاً لنظام Maxlond لإدارة المقاولات والمشاريع المدنية، بالاعتماد حصراً على REST API الموجود أدناه. لا تفترض وجود أي endpoint غير مذكور، ولا تعدّل backend.

رابط API الأساسي:
https://ضع-نطاق-الخادم-هنا/api.php?route=

اللغة والواجهة:
- اجعل العربية اللغة الأساسية والاتجاه RTL في كل الشاشات والنماذج والجداول والرسائل.
- أنشئ واجهة مهيأة للهاتف واللوحي، بسيطة وواضحة، مع حالات تحميل وفراغ وخطأ وانقطاع اتصال.
- استخدم Material 3 ومكونات Flutter أصلية، ونظّم الشيفرة إلى طبقات للشاشات والنماذج والخدمات وإدارة الحالة.
- استخدم حزمتَي http للاتصال وflutter_secure_storage لحفظ التوكن، أو بدائل معروفة إذا كانت موجودة مسبقاً في المشروع.
- لا تضع أسراراً أو كلمات مرور ثابتة داخل التطبيق، ولا تسجل كلمات المرور أو التوكن في console.

المصادقة:
- شاشة دخول باسم مستخدم أو بريد إلكتروني وكلمة مرور، مع حقل اختياري device_info.
- أرسل POST إلى ?route=login بصيغة JSON:
  {"username":"...","password":"...","device_info":"Maxlond Flutter"}
- النجاح يعيد data.token وdata.token_type=Bearer وdata.expires_in وdata.user.
- خزّن data.token في التخزين الآمن، وأرفق في كل طلب محمي:
  Authorization: Bearer 
  Accept: application/json
- أرسل Content-Type: application/json لطلبات JSON.
- عند 401 امسح التوكن وأعد المستخدم إلى الدخول برسالة مفهومة.
- أضف تسجيل خروج باستدعاء POST ?route=logout ثم حذف التوكن محلياً.
- لا توجد نقطة refresh؛ عند انتهاء التوكن يجب تسجيل الدخول من جديد.
- أنشئ شاشة انتظار الموافقة عند خطأ 403 الخاص بالحساب غير المعتمد، ولا تحاول تجاوز صلاحيات الدور.

الأدوار والصفحات:
1. بعد الدخول استدع GET ?route=me لمعرفة role والملف الشخصي.
2. استدع GET ?route=dashboard وأنشئ لوحة حسب الدور:
  - المدير: sites, engineers, machinery, pending_reports, inventory_value, today_top_engineers.
   - المهندس: open_tasks, completed_tasks, pending_reports, approved_reports.
3. أظهر للمستخدم قائمة صفحات حسب role؛ لا تعرض إجراءات لا يدعمها API.

المسارات المتاحة:
- POST ?route=login: دخول دون توكن.
- GET ?route=me: بيانات المستخدم الحالي.
- POST ?route=logout: إبطال توكن الجهاز الحالي.
- GET ?route=dashboard: مؤشرات تختلف حسب الدور.
- GET ?route=sites: قائمة المواقع التي يستطيع المستخدم رؤيتها.
- GET ?route=machinery: قائمة الآليات.
- GET ?route=tasks: المهام؛ يمكن إضافة site_id وstatus كاستعلام.
- POST ?route=task-update: للمهندس فقط، لتحديث مهمة مسندة إليه أو معممة.
- GET ?route=reports: المدير يرى كل التقارير والمهندس تقاريره فقط.
- GET ?route=reports&id=ID: تفاصيل تقرير مع المصروفات والإيصالات؛ يمكن إضافة status أو site_id كمرشح.
- POST ?route=reports: للمهندس فقط، إنشاء/تحديث التقرير اليومي.
- POST ?route=report-review: للمدير فقط، اعتماد تقرير مرسل أو رفضه مع ملاحظات.
- POST ?route=report-receipt: رفع إيصال واحد بصيغة multipart/form-data.
- GET ?route=notifications: إشعارات المستخدم الحالي.
- POST ?route=notification-read: تعليم إشعار واحد كمقروء.
- POST ?route=notification-read-all: تعليم جميع إشعارات المستخدم كمقروءة.

صفحة المواقع والآليات:
- اعرض GET ?route=sites وGET ?route=machinery.
- اعرض حالات المواقع والآليات كنصوص عربية، مع المحافظة على القيمة الإنجليزية الأصلية عند إرسال البيانات إن لزم.
- لا تنشئ عمليات إضافة أو تعديل أو حذف، فلا توجد لها endpoints.

صفحة المهام:
- استدع GET ?route=tasks. مرشحات اختيارية: &site_id=ID و&status=pending أو إحدى الحالات: in_progress, review, done, cancelled.
- اعرض الموقع والعنوان والوصف والأولوية والحالة والتقدم.
- للمهندس فقط، أنشئ نموذج تحديث يرسل POST ?route=task-update:
  {"task_id":12,"progress":65,"status":"in_progress","note":"ملاحظة التنفيذ"}
- progress عدد صحيح بين 0 و100، والحالات المقبولة pending وin_progress وreview وdone.
- حالة done تجعل الخادم التقدم 100. اعرض نتيجة الحفظ وحدّث المهمة محلياً بعد نجاح الاستجابة.
- لا تسمح للمدير بتحديث المهمة من التطبيق عبر هذا المسار.

صفحة التقارير:
- اعرض GET ?route=reports. للمهندس تقاريره فقط، وللمدير جميع التقارير. استخدم GET ?route=reports&id=ID لتحميل التقرير ومصروفاته ومرفقاته.
- أنشئ للمهندس نموذج تقرير يرسل JSON إلى POST ?route=reports بالحقول:
  site_id, report_date بصيغة YYYY-MM-DD, weather, temperature, workers_count, machinery_count, work_done, issues, materials_used, safety_notes, progress_percent, expenses.
- expenses قائمة عناصر، وكل عنصر يحوي item_name وcategory وquantity وunit_price وnotes.
- تصنيفات المصروفات المقبولة: materials, labor, fuel, equipment, transport, other.
- يوجد سجل واحد لكل engineer/site/date. إعادة الإرسال قبل اعتماد المدير تحدث التقرير وتستبدل المصروفات؛ لا تكرر التقرير محلياً.
- إذا عاد HTTP 409 فالتقرير معتمد ومقفل. اعرض للمستخدم أنه يحتاج مراجعة المدير.
- اعرض للمستخدم أن التقرير أرسل وينتظر اعتماد المدير. يمكن للمدير إرسال POST ?route=report-review مع report_id وdecision بقيمة approved أو rejected وحقل admin_notes اختياري.

رفع الإيصالات:
- بعد إنشاء التقرير والحصول على report_id، ارفع كل ملف منفرداً إلى POST ?route=report-receipt بصيغة multipart/form-data.
- حقول النموذج: report_id وreceipt، مع ترويسة Bearer.
- الصيغ المدعومة JPEG وPNG وWebP وPDF، حتى 5MB للملف. تعامل مع 422 إذا رفض الخادم الملف.
- لاسترجاع بيانات المرفقات، استخدم GET ?route=reports&id=ID ثم data.receipts؛ file_path مسار نسبي لجذر التطبيق.

الإشعارات:
- اعرض GET ?route=notifications، وميّز is_read=false.
- تعليم إشعار واحد: POST ?route=notification-read بجسم {"notification_id":28}.
- تعليم الكل كمقروء: POST ?route=notification-read-all دون جسم؛ يعيد updated_count.

التعامل مع الاستجابة والأخطاء:
- النجاح بالشكل {"success":true,"data":...}.
- الخطأ بالشكل {"success":false,"error":{"code":"...","message":"..."}}.
- تعامل مع 200 و201 نجاحاً، و401 بإعادة الدخول، و403 منع صلاحية، و404 مورد غير موجود، و409 تعارض/تقرير معتمد، و422 تحقق مدخلات، و429 تحديد محاولات الدخول، و500 خطأ خادم.
- لا تفترض أن كل فشل شبكة يرجع JSON؛ عالج timeout وانقطاع الإنترنت والاستجابة غير القابلة للتحليل برسالة عامة قابلة لإعادة المحاولة.
- لا تعرض stack trace أو معلومات قاعدة البيانات للمستخدم.

قيود نطاق العمل:
- لا توجد endpoints حالياً لتسجيل حساب جديد، اعتماد المستخدمين، إنشاء وتعديل المواقع والآليات، عمليات المخزن، دليل الحسابات، القيود، التقارير المالية، تنزيل ملفات الإيصالات كتنزيل محمي مستقل، أو تجديد التوكن.
- ضع هذه الأقسام خارج التطبيق أو اعرضها للقراءة فقط عند توفر endpoint قراءة موثق. لا تخترع endpoints.
- إعدادات CORS تسمح بالطلبات، لكن التطبيق الأصلي لا يحتاج CORS على الهاتف عادة؛ استخدم HTTPS بشهادة صالحة في الإنتاج.
